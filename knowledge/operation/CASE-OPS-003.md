# CASE-OPS-003 任务调度异常（路径冲突与任务排队）

## 问题

某搬运项目的机器人在通道口频繁等待，任务排队时间变长，
单台设备运行时长看似不低，但有效作业时间明显不足，运行率与交付效率下降。

## 现象

- 多台设备在少数狭窄节点长时间停留，出现排队现象。
- 单次任务耗时上升，任务完成量下降。
- 设备故障率正常，但运行时长里有较大比例是等待。
- 偶发多台设备相互等待（接近死锁）的情况。

## 可能原因

- 路径规划未考虑通道通行能力，多台设备同时进入同一段路径。
- 任务优先级规则缺失，低优先任务占用关键通道。
- 交通管制策略（单行、会车让行）未配置或配置不合理。
- 现场临时堆放改变了通道宽度，但地图未更新。

## 处理措施

1. 复勘现场并更新地图，标注狭窄路段与临时堆放点。
2. 设置关键通道的交通管制规则（单行、限流、会车点）。
3. 优化任务优先级与派单顺序，避免多台设备同时争夺同一通道。
4. 统计“等待时长占比”，把无效等待与有效作业区分开。

## 处理结果

- 通道等待时间明显减少，单次任务耗时回落。
- 任务完成量提升，运行率的“有效率”改善。
- 未再出现设备互锁等待的情况。

## 经验总结

运行时长足够但产出不足时，应把时间拆成**有效作业 / 等待 / 充电**三段来看；
路径与调度规则的问题不会体现在故障率上，只能通过时间结构发现。
